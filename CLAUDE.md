## What this is

Cross-browser WebExtension (Firefox MV3 + Chrome) that converts Confluence/Jira pages to Markdown and Markdown to Jira wiki markup. No framework, plain JS bundled with esbuild.

## Commands

```bash
npm install
npm run build              # bundle src/ into extension/, sync manifest version
npm run lint               # web-ext lint on extension/
npm run start:firefox      # launch Firefox with extension loaded
npm run package:firefox    # build + dist/firefox/wiki_markdown-{version}.xpi
npm run package:chrome     # build + dist/chrome/ and dist/wiki_markdown-{version}-chrome.zip
npm run package            # both
node test/converter.test.js  # converter smoke tests (only test file, no framework)
```

- Tests bundle `src/converter/index.js` to a temp CJS file and run plain `assert` checks. To run one case, comment out the others; there is no filter flag.
- As of 2026-09-29 the test run crashes at the table case with `TypeError: table.rows is not iterable` (from `confluence-tables.js` under Turndown's Node DOM). Browser behavior is not affected by this.
- Version lives only in `package.json`. `build.js` writes it into `extension/manifest.json`. Bump with `npm version X.Y.Z --no-git-tag-version`, then `npm run package`.

## Build outputs are committed

`extension/content.js`, `extension/lib/converter.bundle.js`, and `extension/lib/browser-polyfill.js` are generated by `npm run build` but tracked in git. Edit `src/`, never these files, and rebuild before committing so they stay in sync.

`src/converter.js` is a legacy monolithic converter. Nothing imports it. The live code is `src/converter/`.

## Architecture

Two separate esbuild bundles run in different contexts:

1. **Converter** (`src/converter/index.js` → `extension/lib/converter.bundle.js`, IIFE global `JiraMdConverter`). Loaded only by the popup (`popup.html` script tags). Public API: `htmlToMarkdown`, `jiraToMarkdown`, `markdownToJira`, `J2M`.
   - `strategies/markdown.js`: HTML → MD via Turndown + GFM + the Turndown plugins in `plugins/` (registered in `plugins/index.js`).
   - `strategies/jira.js`: Jira → MD uses `jira2md`. MD → Jira uses the custom AST pipeline `pipeline/parser.js` → `transformer.js` (visitors) → `emitter.js`.
2. **Content script** (`src/islands/index.js` → `extension/content.js`). "Islands" register handlers by message `type` on `message-bus.js`. Islands never import each other, only `message-bus.js` and `notification.js`. The content script does not include Turndown. The keyboard shortcut path (`shortcut-handler.js`) uses its own lightweight DOM walker, so shortcut output differs from popup output.

Runtime message flow:
- Popup → content script (`browser.tabs.sendMessage`): `getPageInfo`, `extractPageContent`, `exportSingleHtml`, `insertMarkdownToJira`, `collectAttachments`.
- Popup/content → `extension/background.js` (`browser.runtime.sendMessage`): `fetchImagesAsBase64`, `downloadToFolder`, `downloadAttachments`. Background does cross-origin image fetches and downloads.
- Background handles `commands` and context menus, then drives the content script (`extractPageContent` → `convertAndCopy`, `insertFromClipboard`).

Settings are stored in `browser.storage.local` under key `wikiMdSettings`, written by `extension/options/` and read by `popup.js`.

## Firefox vs Chrome

`extension/manifest.json` is the Firefox manifest (gecko id, `menus`, `background.scripts`). The Chrome manifest is derived, not hand-edited: `build.js` and `scripts/package-chrome.js` both remove `browser_specific_settings`, rename `menus` → `contextMenus`, switch to a `service_worker`, and move `optional_host_permissions` into `optional_permissions`. If you change this transform, update both files. Chrome uses `lib/browser-polyfill.js` for the `browser.*` API.

## Conventions (from README)

- One responsibility per file. Add a new plugin, strategy, or island instead of growing an existing one.
- Each Turndown plugin is a standalone file with `filter` + `replacement` rules.
- The `.xpi` is unsigned. Permanent install needs Firefox Developer Edition or Nightly with `xpinstall.signatures.required=false`. Otherwise load `extension/manifest.json` from `about:debugging`.
